03 · The problem Why software now

Good teaching is already happening. The record of it is not.

How institutes typically run

  • Attendance in paper registers or personal spreadsheets
  • Marks trapped in one teacher’s notebook
  • Homework announced once, then lost in a group chat
  • Parents hear updates late, or not at all
  • No audit trail when a mark or role is changed

What DCI Enterprise makes normal

  • Live attendance by class, with history and reports
  • Exams, marks, and PDF report cards from one ledger
  • Homework assigned, tracked, and visible to the student
  • WhatsApp messages from the institute, not from ten phones
  • Roles enforced in the product and in the database
04 · Definition DCI Enterprise

The digital campus of Deshmukh Coaching Institute.

05 · Product map One campus, four surfaces

Every user lands in the same system. The view is different.

DirectorInstitute-wide students, faculty, settings, audit, analytics
AdminDay-to-day operations: users, students, exams, limited settings
TeacherAssigned classes only — attendance, marks, homework, daily report
StudentOwn record, class exams, own results, own homework

Teacher rule that matters

If a teacher has assigned classes, they only see those students. An empty assignment list keeps a broader view. Roles and assigned classes live on the Auth token — users cannot rewrite their own role in Firestore.

06 · Classroom operations The daily loop

The 8:00 a.m. to 8:00 p.m. institute, captured once.

Attendance

Tracker, dashboard, history, and reports. Teachers mark the class they own. Students can see their own history.

Homework

Assign, dashboard, history. Students open “My homework” instead of hunting through a chat thread.

Daily report

A structured close-of-day note from the teacher — what was taught, who struggled, what to revise — stored, not forgotten.

This is the difference between “we take attendance” and “the director can see who was present, in which batch, last Thursday.”

07 · Academic engine Tests → marks → parents

Exams are not an event. They are a ledger.

  • Exam setup and a dedicated exams dashboard
  • Marks entry by teachers on assigned classes
  • Results and comparative views for leadership
  • PDF report cards generated from live data
  • Excel import and export so existing sheets are not a dead end

Why this is enterprise

A mark, once entered, is institute property

Not a screenshot in a group. Not a file on a laptop. The same number the student sees, the parent can be sent, and the director can trend.

09 · Communication WhatsApp is the parent portal

Parents already live in WhatsApp. The institute should too — on purpose.

Device share via wa.me still works for a quick personal ping. Official Cloud API sends go through a server function, with tokens kept off the phone.

  • Announcements feed inside the app
  • Push notifications for staff and students
  • WhatsApp Cloud API callable: sendWhatsAppMessage
  • Public website enquiry path for admissions counselling
  • One number, one voice, one audit path
10 · Trust Security is a product feature

If a student record leaks, the brand leaks with it.

Enforced in the database

Firestore and Storage rules ship with the app. Users cannot change their own role or assigned classes from the client.

Privileged work on the server

Creating staff and sending WhatsApp Cloud messages are Cloud Functions. Secrets stay in the function environment.

Audit and privacy

Administrative actions log through AuditRepository. Privacy policy and terms sit on the public site before launch.
